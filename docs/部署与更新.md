# 部署与更新备忘

## 一句话原理

写文章 → `git push` → Cloudflare Pages 自动构建 → 网站更新。

站点地址：https://baiye.pages.dev
GitHub 仓库：https://github.com/cunninghamcard-bit/baiye
部署分支：`main`

---

## 怎么发一篇新文章（日常就这一套）

```bash
# 1. 生成文章骨架（支持中文标题）
bun run new:post "我的文章标题"
# → 生成 src/content/blog/我的文章标题.md，默认 draft: true

# 2. 写正文（直接编辑那个 .md，或用 Obsidian 打开 src/content/blog 写）

# 3. 本地预览，确认没问题
bun run dev
# → 浏览器打开 http://localhost:4321

# 4. 准备发布：把文章 frontmatter 里的 draft 改成 false
#    draft: true  →  draft: false

# 5. 提交并推送 = 发布
git add .
git commit -m "post: 我的文章标题"
git push
# → 约 1~2 分钟后 baiye.pages.dev 自动更新
```

`draft: true` 的文章不会出现在线上，可以放心 push 半成品。

---

## 改完文章/改配置后怎么更新

跟发文章一样，本质就是三行：

```bash
git add .
git commit -m "说明改了啥"
git push
```

推送后 Cloudflare 自动重新构建部署。

---

## ⚠️ 首次部署：先把博客真正发上去（一次性）

现状：`baiye.pages.dev` 当前挂的是一个遗留的 **nginx 占位页**，真正的博客还没部署过。
自动部署没在工作，需要先在后台把 Pages 项目和 GitHub 仓库连起来。

1. 登录 https://dash.cloudflare.com → Workers & Pages → 点开 `baiye`
2. **Settings → Builds & deployments**：
   - **没连 GitHub** → 点 "Connect to Git"，选仓库 `cunninghamcard-bit/baiye`，
     生产分支 `main`，**构建命令 `bun run build`**，**输出目录 `dist`**，保存
   - **连了但还是 nginx** → 进 Deployments 看最近构建日志，多半是构建报错
3. 绑好后 `git push` 一次 → Cloudflare 自动构建 → nginx 页被博客覆盖

之后的所有更新就只是 `git push`，不用再碰后台。

---

## 备用：命令行手动部署（一般用不到）

只有在「没绑 Git」且想临时手动发的时候才用，需要一个有 Pages 写权限的 token：

```bash
bun run deploy   # = bun run build && wrangler pages deploy --project-name baiye
```

当前登录的 token 只有 Workers 权限，跑这个会报权限错——所以优先用上面的 git push 自动部署。

## 常用命令速查

| 命令 | 作用 |
|------|------|
| `bun run dev` | 本地预览（localhost:4321） |
| `bun run build` | 本地完整构建一遍（排查能不能成功部署） |
| `bun run new:post "标题"` | 新建文章 |
| `git push` | 发布 / 更新线上 |
