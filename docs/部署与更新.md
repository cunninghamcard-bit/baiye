# 部署与更新备忘

## 一句话原理

写文章 → `git push` → Cloudflare Pages 自动构建 → 网站更新。

站点地址：https://baiye-e17.pages.dev
GitHub 仓库：https://github.com/cunninghamcard-bit/baiye
部署分支：`main`

---

## 怎么发一篇新文章（日常就这一套）

```bash
# 1. 生成文章骨架（支持中文标题）
bun run new:post "我的文章标题"
# → 生成 src/content/blog/我的文章标题.md，默认 draft: true

# 2. 写正文（直接编辑那个 .md，或用 Obsidian 打开 src/content/blog 写）

# 3. 本地预览，确认没问题
bun run dev
# → 浏览器打开 http://localhost:4321

# 4. 准备发布：把文章 frontmatter 里的 draft 改成 false
#    draft: true  →  draft: false

# 5. 提交并推送 = 发布
git add .
git commit -m "post: 我的文章标题"
git push
# → 约 1~2 分钟后 baiye-e17.pages.dev 自动更新
```

`draft: true` 的文章不会出现在线上，可以放心 push 半成品。

---

## 改完文章/改配置后怎么更新

跟发文章一样，本质就是三行：

```bash
git add .
git commit -m "说明改了啥"
git push
```

推送后 Cloudflare 自动重新构建部署。

## 部署配置现状（已打通，留作记录）

Pages 项目 `baiye` 已连 GitHub 仓库 `cunninghamcard-bit/baiye`，生产分支 `main`，push 即自动构建。
后台关键设置（Settings → Builds & deployments）：

- **构建命令：`bun install && bun run build`**（必须带 `bun install`——CF 不会自动装依赖）
- **输出目录：`dist`**
- **bun 版本：`1.3.14`**（由 `package.json` 的 `packageManager` 字段锁定）

### 当初为什么一直部署失败（排错记录）

1. `baiye.pages.dev` 那个 nginx 页是**别人的项目**，你的真地址是 `baiye-e17.pages.dev`——看错域名了。
2. 构建命令一度被写成 `bun run builde`（多个 e），改回 `bun run build`。
3. CF 不自动装依赖 → `gray-matter` 找不到，改成 `bun install && bun run build`。
4. CF 旧 `bun@1.1.45` 装的 rolldown 原生绑定与 `@tailwindcss/vite` 不兼容
   （`Missing field tsconfigPaths`）→ 把 `packageManager` 锁到本地可用的 `bun@1.3.14`。

以上都已修好，现在 `git push` 就能正常部署。

之后的所有更新就只是 `git push`，不用再碰后台。

## 备用：命令行手动部署（一般用不到）

只有在「没绑 Git」且想临时手动发的时候才用，需要一个有 Pages 写权限的 token：

```bash
bun run deploy   # = bun run build && wrangler pages deploy --project-name baiye
```

当前登录的 token 只有 Workers 权限，跑这个会报权限错——所以优先用上面的 git push 自动部署。
