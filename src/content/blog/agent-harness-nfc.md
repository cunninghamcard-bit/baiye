## 被边界拦住

我打算录入公司的门禁卡 NFC。

这个需求一开始看起来很简单。手机有 NFC，门禁卡也是 NFC，我只是想把卡录进去，之后用手机刷门禁。

但我的手机是红米刷成 PixelOS。网上找不到适用的录入教程。很多教程只适用于厂商自带系统，或者只讲普通 Android 的 NFC 设置。

我于是问 ChatGPT，它给了很多常见建议，比如检查 NFC、确认系统支持、找钱包应用、注意门禁卡加密。

这些建议没有用处，如果他做不到网上的现有教程，他的回答maybe is just ai slop，他给的只是泛化知识：我还是不知道下一步该做什么。它没有告诉我该用什么工具验证，也没有告诉我失败之后怎么判断原因。

**这就是标准的chatbot，就像搜索引擎，搜索，然后给一个模棱两可似是而非的结果。**

这和目前诸多大厂 app 里面塞进去的 chat 按钮一样，给出无人在意的答案，随便污染一下视野。 

---------BTW，我很讨厌RAG，我也不喜欢背rag八股文，希望我秋招的时候不要碰到这些贴着Agent标签的RAG岗位

## 做得到的事情

这些鸡肋/useless 的情况似乎表明，即使 RAG 和搜索做得再好，对于互联网来说，也仍然有太多信息是获取不到的。更何况目前 agent 的搜索和调研也是差强人意。

我们能找到的信息太少，他能做的事情太少。

我当时没有意识到 agent 的能力边界。
 
 ### 偶然，我只是让它修复一个问题。

经过翻阅网上的诸多攻略，我下载了很多 NFC emulator 软件，又在一次又一次失败之后，我怒而删除这些软件。结果我把 NFC 功能搞坏了，手机上的 NFC 图标怎么也点不开。

于是我才想到把 Codex 连到手机，让它通过 adb 来修复。

**这里还有另外一个问题：为什么 agent 一开始没有叫我用 adb 连接手机来调试？**

因为它搜索不到，它也不知道。也许未来有一篇又一篇攻略教人这么做，它才会知道这是一种做法。

接下来无非是它发现几个软件和配置上的问题，继续处理。也是在这个过程中，我突然想到：既然它可以修复 NFC 功能和配置，不如直接让它来写NFC。

接下来无非是侥幸成功，codex 完美的把nfc直接写入了我的手机，就像写一个函数。

## 人是 agent 的瓶颈吗

我们常常听到一种说法：人是 agent 的瓶颈。

比如人 review 太慢，agent 写代码比人看代码快很多。

但这个场景里，瓶颈没有那么简单。

如果我对 adb 一无所知，Codex 也很难帮我解决这个问题。因为它没有主动指出 adb 这条路。它停在搜索、教程、常见建议里面，直到我自己想到adb能够连接agent 和手机。

**这里就出现了一个反过来的问题：到底是人限制了 agent，还是 agent 不够 smart，没法帮用户指出下一条可走的路？**

也许这里也有用户的问题。prompt 不够好，问题描述不够完整，没有把手机环境、系统状态、可连接工具这些条件说清楚。

但更关键的是，目前 agent 很难知道自己的 harness 还能怎么扩展。

它知道自己现在有什么工具，却不一定知道“我还可以让用户给我什么工具”。

很多时候 agent 失败，不一定卡在某个具体任务本身，也会卡在迁移现场这一步。比如从搜索迁移到 adb，从回答方案迁移到查看日志，从猜测原因迁移到直接验证设备状态。

人可能是 agent 的瓶颈，但 agent 也会被自己的 harness 困住。更准确的问题是：人和 agent 怎么共同意识到，当前 harness 不够了，需要扩展。

## 为什么还需要人 building agent

这也许解释了为什么现在还需要人去 building agent。

模型对 agent 的概念被训练语料限制了。它了解的往往是一两年前某个 LangChain 项目里的 agent：规划、调用工具、返回答案。

但现在更重要的是 harness。

harness 能让模型完成原本无法完成的任务。它给模型一个可验证的环境，也给它一双手。

比如 adb 没有直接给出答案，它把手机变成了 agent 可以观察、操作、验证的现场。

**问题在于，agent 自己不擅长 building harness，也不擅长寻找 harness**，或者说明天也许他知道了harness是什么？然后又出现了一个新的概念。

它会使用已经给到的工具，却很难主动说：这个问题不该继续搜索了，我需要 adb；这个问题不该继续猜了，我需要直接看设备状态。

所以目前还需要人参与 building agent。

人要做的事情，是指出新的现场在哪里，告诉 agent 还能把哪些东西接进来。

这次 NFC 的成功带有侥幸。

我一开始没有设计一个 adb harness。我只是把问题搞坏到需要修复手机，才让 Codex 进入了手机现场。

但这个侥幸暴露了一个方向：好的 agent 以后应该更早发现这种入口。

它不应该只在已有工具里打转，也不应该只等用户把工具摆到它面前。

**它至少应该能问出下一步：这个问题有没有一个可以连接、可以观察、可以验证的现场？**
